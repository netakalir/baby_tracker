# זרימת משתמש מלאה: מאפס עד מסך "היום"

## תוספת חשובה למודל הדאטה - טבלת הזמנות

כדי שהורה ב' יוכל "להצטרף" למשפחה שהורה א' יצר, צריך מנגנון הזמנה. זה לא היה במודל המקורי - תוספת:

### `family_invites`
| עמודה | טיפוס | הערה |
|---|---|---|
| id | uuid (PK) | |
| family_id | uuid (FK -> families) | |
| invited_by | uuid (FK -> auth.users) | מי שלח את ההזמנה |
| token | text (unique) | קוד אקראי בקישור ההזמנה |
| created_at | timestamp | |
| expires_at | timestamp | למשל 7 ימים מיצירה |
| used_at | timestamp (nullable) | null = עדיין לא נוצל |
| used_by | uuid (FK -> auth.users, nullable) | מי השתמש בקישור |

**RLS להזמנות:** רק חבר במשפחה יכול ליצור הזמנה לאותה משפחה. כל אחד (גם לא מחובר) יכול **לקרוא** הזמנה בודדת לפי token תקף (כדי לבדוק אותה לפני הרשמה) - אבל לא לרשום רשימה של כל ההזמנות.

## תרשים זרימה - משתמש ראשון (יוצר המשפחה)

```
1. נחיתה באפליקציה (לא מחובר)
   ↓
2. מסך Auth - "התחברות / הרשמה"
   [Sign up with Email] [Sign up with Google]
   ↓
3. הרשמה מוצלחת → אין family עדיין
   ↓
4. מסך "צור משפחה או הצטרף"
   [צור משפחה חדשה]   [יש לי קישור הזמנה]
   ↓ (בוחר "צור משפחה")
5. טופס קצר: שם המשפחה (אופציונלי, default: "המשפחה שלי")
   → נוצרת רשומה ב-families
   → המשתמש מתווסף ל-family_members עם role="parent"
   ↓
6. מסך "הוסף את הילד הראשון"
   שדות: שם, תאריך לידה
   → נוצרת רשומה ב-children
   ↓
7. (אופציונלי, לא חוסם) "רוצה להזמין את ההורה השני?"
   [שלח הזמנה] [דלג, אעשה זאת בהמשך]
   → אם בוחר לשלוח: נוצר token ב-family_invites, מוצג קישור להעתקה/שיתוף בוואטסאפ
   ↓
8. מסך "היום" - Empty State
   השעון ריק, הודעה: "עדיין אין נתונים היום - לחץ על אחד הכפתורים כדי להתחיל"
```

## תרשים זרימה - משתמש שני (מצטרף לקיים)

```
1. מקבל קישור הזמנה (וואטסאפ/SMS) בפורמט:
   https://app.../join?token=XXXXX
   ↓
2. לוחץ על הקישור → האפליקציה נפתחת
   ↓
3. בדיקת תוקף ה-token (ללא צורך בהתחברות עדיין):
   - אם expired/used → מסך שגיאה: "ההזמנה הזו לא תקפה יותר, בקש קישור חדש"
   - אם תקף → ממשיכים
   ↓
4. מסך Auth (אם עדיין לא מחובר) - "התחברות / הרשמה"
   ↓
5. אחרי הרשמה/התחברות מוצלחת:
   → נוצרת רשומה ב-family_members (אותו family_id, role="parent")
   → ה-invite מסומן used_at + used_by
   ↓
6. מסך "היום" - אבל **לא Empty State** הפעם!
   רואה את הילד שכבר קיים, ואת כל הנתונים שהורה א' הזין
```

## מצבי קיצון שזוהו בתהליך הזה

| מצב | טיפול מוגדר |
|---|---|
| המוזמן לוחץ על קישור אבל **כבר** מחובר עם חשבון אחר | להציג אזהרה: "אתה מחובר כ-X, האם להמשיך ולהצטרף עם החשבון הזה?" |
| ההזמנה כבר נוצלה ע"י מישהו אחר | הודעת שגיאה ברורה, לא ליצור שיוך כפול |
| **משתמש שכבר חבר במשפחה לוחץ על קישור הזמנה למשפחה אחרת** | **הוחלט (MVP):** חסימה מלאה. הצטרפות נכשלת, מוצגת הודעה: "אתה כבר חבר במשפחה אחת. האפליקציה תומכת במשפחה אחת בלבד למשתמש בשלב זה." ה-invite **לא** מסומן used_at - נשאר תקף לניצול ע"י משתמש אחר. ראו `error-handling-spec.md` לקוד השגיאה המדויק |
| משתמש סוגר את הדפדפן באמצע יצירת משפחה (לפני יצירת ילד) | בכניסה הבאה - הוא חבר במשפחה בלי ילד; המסך הבא הוא "הוסף ילד" ולא "צור משפחה" מההתחלה |
| היוצר לא מזמין אף אחד ונשאר משתמש בודד | זה תקין - האפליקציה עובדת גם עם הורה אחד, ההזמנה היא תמיד אופציונלית ולא חוסמת |

## קריטריון קבלה (Acceptance Criteria) לזרימה הזו
- [ ] משתמש חדש יכול להירשם ולהגיע למסך "היום" תוך 3 צעדים לכל היותר (לא כולל הזמנת הורה שני)
- [ ] שני הורים יכולים להיות באותה family ולראות את אותו ילד/אירועים
- [ ] קישור הזמנה שפג תוקפו מציג שגיאה ברורה ולא שגיאת מערכת גנרית
- [ ] משתמש לא יכול "להצטרף" פעמיים לאותה משפחה (אם כבר חבר, מובל ישר ל"היום")

---

## מה עדיין לא הוגדר בזרימה הזו (להמשך)
- מסך "Empty State" המדויק - טקסט, עיצוב, האם יש אנימציה/איור
- תהליך "שכחתי סיסמה" (Supabase Auth מספק את זה מובנה - רק להחליט על עיצוב המסך)
- מה קורה ב-UI בדיוק כשהזמנה ממתינה (האם רואים "הזמנה נשלחה, ממתין/ה")
